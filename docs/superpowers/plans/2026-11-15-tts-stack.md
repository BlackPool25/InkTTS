# TTS Stack + Orchestrator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Boot `docker compose up` into a LAN TTS stack (Kokoro CPU + Chatterbox Turbo GPU + orchestrator) that renders per-sentence Opus with timings and serves it over one LAN-open port.

**Architecture:** Adopt `remsky/Kokoro-FastAPI` (CPU) and `devnen/Chatterbox-TTS-Server` (Turbo) as-is; our only server code is a thin FastAPI orchestrator owning the preempt queue, sentence cache (SQLite WAL + sharded files), unified Enhanced-LRC timings, SSE progress, and an OpenAI-compat shim.

**Tech Stack:** Docker Compose (NVIDIA runtime, cu128), Python 3.12 + FastAPI, SQLite WAL, pytest.

**Spec:** `docs/superpowers/specs/2026-11-15-extension-tts-design.md`

## Global Constraints

- Kokoro on CPU only — zero VRAM, always warm.
- Chatterbox Turbo lazy-loads, idle-evicts via `/api/unload` timer — GPU empty at rest.
- No cloning ever — Chatterbox stock voices only.
- English-only v1; non-English fails loud.
- LAN-open plain HTTP, single published port; no auth wall.
- Every commit `git commit -s`.
- Image tags pinned (no `:latest`); one shared HF-cache volume so updates never re-download weights.

## Review Focus

- NovelBuddy bot-challenge page fed as chapter text → must hard-block with `challenge` error, never narrate it (test in Task 5).
- Chatterbox GPU down mid-chapter → those sentences degrade to Kokoro with `degraded:true`, never silent swap, never hang (test in Task 3).
- Rapid taps (seek storm: 10 taps in 2s) → newest wins, no more than 1 Kokoro + 1 Chatterbox in flight, nothing lost (test in Task 4).
- Cache disk full / over cap → oldest LRU evicted before insert, write never fails the render (test in Task 2).
- Chapter re-fetch with identical text → zero re-renders, all cache hits (test in Task 3).
